# Official Higgsfield skill-method fusion (offline only)

This reference translates three official Higgsfield skills into the existing
`cinematic-ai-director` production system:

- `higgsfield-generate` 0.12.0;
- `higgsfield-soul-id` 0.12.0;
- `higgsfield-product-photoshoot` 0.12.0.

The translation is methodological, not operational. The Skill never installs
the Higgsfield CLI, authenticates an account, uploads media, trains a Soul,
submits a generation, polls a job, or consumes credits. Deliverables remain
local authority assets, manifests, prompts, review boards, edit/audio plans,
and the portable offline Higgsfield package.

## Evidence classification

Adopt directly when the rule remains useful across providers:

- classify intent before choosing a generation path;
- give every reference an explicit input responsibility;
- keep model-facing instructions concise and put audit facts in sidecars;
- treat identity source quality, diversity, rights, and consent as gates;
- lock product truth before making campaign derivatives;
- select a product-photography mode from the actual placement and objective;
- treat image, video, audio, and video analysis as different task families.

Translate rather than copy when behavior is provider-specific:

- live model-schema discovery becomes an operator preflight recorded in the
  offline package;
- model names become dated advisories, never timeless authority;
- Soul training becomes a local source-readiness record;
- Product Photoshoot becomes a short intent brief plus product truth lock;
- generation commands become reference-role maps and work orders.

Do not emulate:

- Soul model training or reusable provider reference IDs;
- the Product Photoshoot backend prompt enhancer;
- Marketing Studio entities, presets, or server-side brand memory;
- account, upload, generation, polling, analysis, or credit behavior.

## Unified production flow

1. Read the script, commercial brief, product facts, identity requirements,
   format, runtime, placement, and sound needs.
2. Classify each requested output by intent before writing a prompt.
3. Build project authority assets with built-in ImageGen and the existing
   clean live-action gates.
4. For a recurring fictional person, use one approved single-solve Inspector
   board as first identity authority. For a real person, also build a separate
   lawful-photo readiness record if the user wants future Soul compatibility.
5. For a product, approve the product authority and truth lock before any
   lifestyle, person-with-product, campaign, or video derivative.
6. Compile short model-facing facts while retaining complete geometry,
   spatial, continuity, rights, QA, and reconstruction facts in JSON.
7. Approve by Foundation and sequence gates as before.
8. Export the same offline production package, augmented with method routing,
   Soul readiness, Product Photoshoot intent, and audio work orders.

## Intent-first generation routing

`higgsfield-generate` distinguishes task families rather than treating one
model as universal. Preserve that reasoning in `generation_routes`.

| Intent | Local capability family | Snapshot advisory only | Required local facts |
|---|---|---|---|
| General image/design/text | `general_image` | GPT Image 2 | prompt purpose, aspect, approved references |
| Character/reference image | `reference_image` | Nano Banana family or Soul-compatible still | identity/state responsibilities and order |
| Cinematic still | `cinematic_still` | Soul Cinematic | approved identity/location/profile; not a generic style word |
| Empty location | `location_image` | Soul Location | topology, state views, spatial anchor, no people |
| Serious production video | `serious_video` | Seedance 2.0 | start/end/reference roles, motion, camera, timing, audio |
| Reference edit/extension | `reference_video` | Seedance 2.5 | explicit mode and image/video/audio reference roles |
| Highest-fidelity cinema | `cinema_grade_video` | Cinema Studio family | shot package and current schema preflight |
| Commercial/ad video | `marketing_video` | Marketing Studio | objective, product, presenter, placement, mode, rhythm, sound |
| Audio/SFX/ambience/music-like | `audio_generation` | Seed Audio | duration, scene timing, source perspective, mix role |
| Finished-video attention review | `attention_analysis` | Virality Predictor | returned user video and analysis purpose |
| Product campaign still | `product_photoshoot` | Product Photoshoot | approved product truth plus one intent mode |

These names describe the 2026-08-31 official-skill snapshot. A later human
operator must inspect the current platform schema; the Skill does not do so and
must not silently replace a preferred route with a cheaper or numerically newer
one. In particular, a version number alone does not prove a strict upgrade:
reference roles, resolution, duration, and output behavior differ by model.

Each route records:

- task kind and visual/audio intent;
- scene, sequence, shot, asset, or deliverable scope;
- one role for each reference asset, in deterministic order;
- capability family and dated model advisory;
- current-schema verification requirement;
- preferred prompt budget and any justified overage;
- output contract;
- `platform_operation: not_performed`.

Do not mix semantically different media roles. A start frame is not a generic
style image, an audio reference is not an instruction to invent sound, a
sequence anchor cannot replace identity/location roots, and product references
cannot replace a product truth record.

## Prompt economy and reference behavior

The official general-generation guidance warns that very long prompts make
details compete. Apply that lesson without discarding this Skill's production
facts:

- target about 200 model tokens when the task permits;
- allow up to 260 only for a structured production reason;
- keep one visible fact in one place instead of repeating it in style, scene,
  character, lighting, and exclusions;
- keep at most four compact hard exclusions for ImageGen;
- store QA, rights, hashes, continuity tables, measurement evidence, and
  failure categories outside the model prompt;
- for image editing, describe the bounded change and preservation contract;
- for image-to-video, let approved frames carry appearance and concentrate the
  prompt on motion, performance, camera path, optics/focus/exposure, physics,
  timing/motion blur, weather response, and sound;
- use positive, observable locks where possible, but retain the existing hard
  rejection gate for oil-film skin, smeared surfaces, animation/CG/game
  rendering, copied cross-material texture, and impossible geometry.

Prompt brevity is not permission to remove spatial coordinates, start marks,
identity/state bindings, product truth, finite dynamic range, camera path,
temporal sampling, or material interaction. The compiler chooses only the
subset that changes visible output; the complete facts remain authoritative in
the package.

## Soul readiness without Soul training

The official Soul skill describes a real-person training set, not a fictional
character turnaround. Keep these responsibilities separate.

Project identity authority:

- one high-resolution `3×2` single-solve Inspector;
- full body front / casting-relevant side / back;
- face front / left profile / right profile;
- one identity, body, wardrobe, white background, neutral light, and capture
  geometry across the whole board;
- deterministic non-resampled crops only after the whole board passes.

Optional real-person Soul readiness:

- 5–20 unique source photographs; 8–12 is the preferred working range;
- one person in each image, clear face, visible eyes, sharp focus;
- no heavy filters or sunglasses;
- varied front/three-quarter/slight vertical angles;
- varied indoor/outdoor or soft/hard lighting;
- varied neutral/smiling/talking expressions;
- varied headshot, head-and-shoulders, and full-body distance;
- JPEG or PNG; approximately 1024×1024 or greater is an ideal source floor;
- confirmed reference rights and affirmative likeness consent.

Only approved `provided` photographs may enter a qualified readiness set.
Generated Inspector panels, state images, bridge frames, failed candidates,
scraped web images, group photos, and repeated near-duplicates do not count.
The Inspector remains the film's identity authority; the real-photo set exists
only as a local future-use readiness record. `platform_training_performed` is
always false.

For a fictional person, do not relabel the Inspector as Soul training data.
Export it in the fictional-character preparation record, with current state
kept separate from immutable identity and temporary performance kept in the
shot prompt.

## Product authority before product photography

Every persistent product receives one product authority containing:

- an approved master and any necessary front, side, rear, three-quarter,
  label, closure, interior, texture, and scale references;
- geometry and silhouette;
- exact visible label text and hierarchy;
- logo placement, scale, orientation, and clear space;
- approved color ranges;
- material construction and physically plausible reflection/roughness;
- dimensions and one scale reference;
- movable parts, fill level, closure, screen, contents, or articulation;
- must-preserve details;
- explicitly allowed state changes;
- source rights and product-fidelity QA.

Product QA checks geometry, label/copy, logo, color, material response, scale,
ground/contact/support, and source traceability. A visually attractive image
fails if the SKU, cap, seam, screen, label, proportions, or material changes.
Lifestyle dirt, condensation, splashes, wear, fingerprints, or cosmetic gloss
must be localized state evidence with a cause; none may become a generic
texture layer.

## Product Photoshoot intent modes

Choose one mode by output purpose. A word in the prompt does not outrank the
placement or deliverable.

| Mode | Use |
|---|---|
| `product_shot` | neutral, studio, catalog, ecommerce |
| `lifestyle_scene` | credible real-world use, hands, action, atmosphere |
| `closeup_product_with_person` | tight demonstration, application, holding |
| `moodboard_pin` | vertical Pinterest-native moodboard |
| `hero_banner` | wide website, email, campaign, or landing-page header |
| `social_carousel` | 3–10 connected slides |
| `ad_creative_pack` | 3–10 coordinated paid-social variants |
| `virtual_model_tryout` | product worn/used by an approved fictional model |
| `conceptual_product` | intentionally surreal, sculptural, floating, splash/CGI concept |
| `restyle` | change an existing image's context while preserving its subject |

Tie-break by deliverable: Pinterest wins over kitchen; banner wins over “in
use”; carousel wins over multiple scenes; close product demonstration wins
over generic lifestyle.

The local brief records product authority IDs, a short intent, placement,
count, optional aspect, approved references, and QA notes. It must state:

- `backend_prompt_owner: higgsfield-product-photoshoot-backend-enhancer`;
- `enhanced_prompt_exported: false`;
- `platform_generation_performed: false`.

The Skill can still use its own ImageGen prompt compiler to create local
authority or narrative assets. It must not call that local prompt an official
Product Photoshoot enhanced prompt.

## Commercial video and product stills are different layers

Product Photoshoot plans branded stills. Marketing-video reasoning plans UGC,
tutorial, unboxing, product showcase, review, TV spot, try-on, or experimental
video. The Skill does not execute either, but commercial direction should still
separate:

- product authority and still intent;
- presenter identity and state;
- opening hook or reference-driven approach;
- environment/setting;
- product proof and action;
- exact runtime, shot function, edit cadence, speed palette, sound, endboard,
  CTA, and delivery matrix.

Do not combine a reference-driven ad approach with a separate hook/setting
approach as if both were independent controls. Select one causal creative
route, then build all frames and shots from the approved brand/product facts.

## Audio work orders

Audio is not a single BGM field. Record dialogue/VO, ambience, Foley, impacts,
transitions, music, mnemonic, perspective, duration, timing, and mix hierarchy.
The offline export may note Seed Audio as the current general advisory, but the
name is not authority and no audio is generated.

For every commercial:

- bind BPM, meter, downbeat, energy curve, shot duration, action peaks, and cut
  relations before choosing slow motion;
- reject a fast track laid under uniform overcranked low-energy footage unless
  a deliberate half-time or counterpoint plan creates readable internal events;
- separate generated-audio intent from an audio reference role;
- preserve picture-linked ambience and Foley even when music dominates;
- record final mix hierarchy and destination delivery.

## `manifests/higgsfield-methods.json`

The manifest contains:

- dated official skill profile and primary-source URLs;
- exact all-false execution boundary;
- adopted, translated, and provider-only method lists;
- generation routes;
- Soul readiness records;
- product authorities;
- Product Photoshoot intent briefs.

The validator blocks:

- any recorded platform operation;
- a generated board counted as a qualified real-photo Soul set;
- fewer than 5 or more than 20 qualified Soul photos;
- missing rights or likeness consent;
- an unapproved or geometrically unstable product authority;
- a product derivative that changes protected product truth;
- an invalid Product Photoshoot mode, count, or aspect;
- a fabricated/exported backend-enhanced prompt;
- ambiguous reference roles;
- mutually exclusive audio/image reference families in one audio route;
- a model advisory treated as current schema authority.
